# Data Model: Staff Authentication

**Feature**: 002-staff-auth | **Date**: 2026-09-24

## Entity: StaffUser (table `StaffUsers`)

| Column | Type | Rules |
|--------|------|-------|
| `Id` | `uniqueidentifier` | Primary key, generated by the application |
| `Email` | `nvarchar(256)` | Required. As entered at creation (trimmed) |
| `NormalizedEmail` | `nvarchar(256)` | Required. Trimmed, upper-cased invariant. **Unique index** `IX_StaffUsers_NormalizedEmail` |
| `PasswordHash` | `nvarchar(500)` | Required. One-way hash only; the plain password is never stored, logged or returned |
| `Role` | `nvarchar(20)` | Required. Exactly `Admin` or `Agent`, enforced by a check constraint `CK_StaffUsers_Role` and by the domain type |

- One user has exactly one role. No other role value can be stored.
- No money columns; nothing here uses `decimal(18,2)`.
- No `Customers`, `Products` or `Invoices` tables (out of scope).

## Domain type

- `StaffRole` — enumeration `Admin`, `Agent` (Domain). Role names used in tokens and policies are
  the enumeration names.
- `StaffUser` — Domain entity with the fields above; creation validates the email is non-empty and
  the role is a defined value.

## Migration

- `AddStaffUsers` (Infrastructure, first real migration). Applied with
  `dotnet ef database update`. Never edited after it has been applied; later changes get new
  migrations.

## Session (not persisted server-side)

The token issued at sign-in. Claims:

| Claim | Value |
|-------|-------|
| `sub` | `StaffUser.Id` |
| `email` | `StaffUser.Email` |
| `role` | `Admin` or `Agent` |
| `jti` | Random id per token |
| `iat` / `nbf` / `exp` | Issue time / same / issue time + `Jwt:ExpiryMinutes` (default 60) |
| `iss` / `aud` | `Jwt:Issuer` / `Jwt:Audience` |

No token is stored on the server; sign-out is client-side (spec assumption).
