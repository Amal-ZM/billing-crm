# Data Model: Invoices

**Feature**: 005-invoice-create | **Date**: 2026-09-24

## Sequence: `InvoiceNumbers`

Start 1, increment 1, minimum 1, maximum 999,999, no cycle. Drawn with `NEXT VALUE FOR` when an invoice row is inserted.
Gaps are possible (a failed save after the draw); duplicates are not.

## Entity: Invoice (table `Invoices`)

| Column | Type | Rules |
|--------|------|-------|
| `Id` | `uniqueidentifier` | Primary key, generated by the application |
| `Number` | `int` | Required. Default `NEXT VALUE FOR [InvoiceNumbers]`. **Unique index** `IX_Invoices_Number`. Shown as `INV-` + six digits |
| `CustomerId` | `uniqueidentifier` | Required. Foreign key to `Customers.Id`, restrict. Index `IX_Invoices_CustomerId` |
| `Status` | `nvarchar(20)` | Required. `Draft` only in this spec, enforced by the domain enum and check constraint `CK_Invoices_Status` |
| `DueDate` | `date` | Required. Not before "today" (UTC+03:00) on create; an unchanged value is always accepted on edit |
| `Notes` | `nvarchar(1000)` null | Optional. Trimmed; empty becomes `NULL`. Line breaks kept |
| `CreatedAtUtc` | `datetime2` | Required. Set once, from `TimeProvider` |
| `UpdatedAtUtc` | `datetime2` | Required. Equals `CreatedAtUtc` on creation; moves only on a real change |

- Indexes: `IX_Invoices_Number` (unique), `IX_Invoices_CustomerId`, `IX_Invoices_CreatedAtUtc_Number` (list order).
- No money columns on the invoice itself (totals belong to a later spec).

## Entity: InvoiceLine (table `InvoiceLines`)

| Column | Type | Rules |
|--------|------|-------|
| `Id` | `uniqueidentifier` | Primary key, generated by the application (`ValueGeneratedNever`) |
| `InvoiceId` | `uniqueidentifier` | Required. Foreign key to `Invoices.Id`, cascade. Index `IX_InvoiceLines_InvoiceId_Position` (**not** unique). Index `IX_InvoiceLines_ProductId` (for the restrict foreign key) |
| `Position` | `int` | Required. Order added, 1-based, never renumbered |
| `ProductId` | `uniqueidentifier` | Required. Foreign key to `Products.Id`, restrict. Reference only, never joined for display |
| `ProductName` | `nvarchar(200)` | Required. **Snapshot** of `Products.Name` when the line was added |
| `ProductSku` | `nvarchar(50)` | Required. Snapshot of `Products.Sku` |
| `Unit` | `nvarchar(20)` | Required. Snapshot of `Products.Unit` (`Hour`, `Item`, `Service`), check constraint `CK_InvoiceLines_Unit` |
| `UnitPrice` | `decimal(18,2)` | Required. **Snapshot** of `Products.UnitPrice` (SAR); check `>= 0` (`CK_InvoiceLines_UnitPrice`) |
| `VatPercent` | `decimal(5,2)` | Required. **Snapshot** of `Products.VatPercent`; check `BETWEEN 0 AND 100` (`CK_InvoiceLines_VatPercent`) |
| `Quantity` | `decimal(9,2)` | Required. `> 0` and `<= 999999.99` (`CK_InvoiceLines_Quantity`). "At most two decimals" is the column scale, not a check (SQL would round a third decimal), so the validator refuses it before saving. Editable on a Draft |

- The snapshot columns are written once when the line is created and never rewritten.
- There is no "line total" or "VAT amount" column: this spec stores quantity, unit price and VAT percent only.
- At least 1 and at most 100 lines per invoice is a service rule (a database cannot count rows in a check).

## State: status

```text
(created) --> Draft
```

- Only `Draft` exists. Later specs add statuses and the transitions between them, each with its own migration that widens
  `CK_Invoices_Status`. A Draft can be edited (header and lines); the edit rules are in research R7.

## Domain types

- `InvoiceStatus` (Domain enum): `Draft`.
- `InvoiceNumber` (Domain static): `Format(int)` gives `INV-000123`; `TryParse(string, out int)` for later lookups.
- `Invoice` (Domain aggregate root): `Create(customerId, dueDate, notes, nowUtc)` (Draft, equal timestamps), `Lines`
  (read-only view ordered by `Position`), `AddLine(...)`, `RemoveLine(id)`, `UpdateDetails(customerId, dueDate, notes, nowUtc)`
  and `SetLineQuantity(lineId, quantity, nowUtc)`; each change method returns whether anything really changed and moves
  `UpdatedAtUtc` only then.
- `InvoiceLine` (Domain entity): `CreateFrom(position, product, quantity)` (internal: only the aggregate calls it, and the validator is the only gate) copies name, SKU, unit, unit price and VAT percent
  from the product **once**; only `Quantity` can change, and only through the aggregate (`Invoice.SetLineQuantity`).

## Application types

- `InvoiceInput(string? CustomerId, string? DueDate, string? Notes, IReadOnlyList<InvoiceLineInput>? Lines)` for add and edit;
  `InvoiceLineInput(string? Id, string? ProductId, decimal? Quantity)`.
- `InvoiceDto` (id, number text, status, customer `{id, name, isActive}`, due date, notes, timestamps, lines),
  `InvoiceLineDto` (id, position, productId, productName, sku, unit, unitPrice, vatPercent, quantity),
  `InvoiceSummary` (id, number text, status, customerId, customerName, dueDate, createdAtUtc).
- `InvoiceQuery(Page, PageSize)` as strings parsed by the service; `PagedResult<T>` reused unchanged.

## Migration

- `AddInvoices` (Infrastructure): the sequence, both tables, indexes and check constraints above. Applied with
  `dotnet ef database update`. Never edited after it has been applied.
- `NoCacheInvoiceNumbers` (Infrastructure): `ALTER SEQUENCE [InvoiceNumbers] NO CACHE`, so an unclean SQL Server stop cannot skip numbers. EF cannot express NO CACHE, so it is raw SQL; a smoke test checks `sys.sequences.is_cached = 0`. A number used by a save that rolled back is still never reused (a sequence does not give numbers back), so a gap after a *failed* save is possible and accepted.

## Configuration

No new settings and no secrets.
