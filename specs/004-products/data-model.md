# Data Model: Products

**Feature**: 004-products | **Date**: 2026-09-24

## Entity: Product (table `Products`)

| Column | Type | Rules |
|--------|------|-------|
| `Id` | `uniqueidentifier` | Primary key, generated by the application |
| `Name` | `nvarchar(200)` | Required. Trimmed. Any script (Arabic, Latin, mixed) |
| `Sku` | `nvarchar(50)` | Required. Stored **already normalized**: trimmed, upper-case, only `A-Z`, `0-9`, `-`, `_`. **Unique index** `IX_Products_Sku` |
| `Unit` | `nvarchar(20)` | Required. Exactly `Hour`, `Item` or `Service`, enforced by the domain enum and check constraint `CK_Products_Unit` |
| `UnitPrice` | `decimal(18,2)` | Required. SAR. 0.00 to 999,999,999.99, at most two decimals (refused, never rounded). Check constraint `CK_Products_UnitPrice` (`>= 0`) |
| `VatPercent` | `decimal(5,2)` | Required. 0.00 to 100.00. Default 15 applied by the service on add only. Check constraint `CK_Products_VatPercent` (`BETWEEN 0 AND 100`). A percentage, not money |
| `IsActive` | `bit` | Required. `true` when created |
| `CreatedAtUtc` | `datetime2` | Required. Set once, from `TimeProvider` |
| `UpdatedAtUtc` | `datetime2` | Required. Equals `CreatedAtUtc` on creation; updated on any real change |

- Indexes: `IX_Products_Sku` (unique), `IX_Products_Name` (list sort order).
- Uniqueness covers **all** products, active and inactive: a deactivated product keeps its SKU.
- The database default collation ignores letter case, but uniqueness does not rely on it: the stored SKU is
  already upper-case.
- No stock or quantity columns (spec FR-020). No foreign keys yet; invoice lines (later spec) will refer to
  `Products.Id` **and copy price and VAT into the line** rather than joining to the live product.

## State: active / inactive

```text
Created --> Active  <----->  Inactive
```

- Only an Admin may toggle, in either direction, any number of times.
- Inactive products keep every field and their reserved SKU. Setting the value a product already has changes
  nothing (including `UpdatedAtUtc`).
- Visibility: Admin sees active only by default and may ask for `inactive` or `all`; Agent always sees active
  only, and an inactive product opened by id is "not found" for an Agent.
- An Admin may still edit an inactive product (for example to correct it before reactivating).
- The invoice spec will read `IsActive` to offer only active products; this spec does not enforce that.

## Domain types

- `ProductUnit` (Domain enum): `Hour`, `Item`, `Service`.
- `Product` (Domain entity): fields above; `Create(...)`, `Update(...)`, `SetActive(...)` that set the timestamps
  passed in by the service; `Update` returns `true` only if something changed (as `Customer`).

## Application types

- `ProductDto` (all fields plus timestamps), `ProductListItem` (id, name, sku, unit, unitPrice, vatPercent,
  isActive).
- `ProductInput` (name, sku, unit as nullable strings; `unitPrice` and `vatPercent` as `decimal?`), one type for add
  and edit. `SetActiveRequest` is reused from customers if it is not customer-specific, otherwise a
  product-side twin with the same shape (decided at implementation, no new concept either way).
- `ProductQuery(Q, Unit, Status, Page, PageSize)`: all **strings** exactly as they arrive in the query string, so a
  bad value becomes a named field error. The service parses it into the validated
  `ProductSearch(Text, Unit, StatusFilter, Page, PageSize)`, where `StatusFilter` is `Active`, `Inactive` or
  `All`.
- `PagedResult<T>` is reused unchanged.
- `ValidProduct(Name, Sku, Unit, UnitPrice, VatPercent)`: validated, trimmed, normalized values.

## Migration

- `AddProducts` (Infrastructure). Applied with `dotnet ef database update`. Never edited after it has been
  applied; later changes get new migrations.

## Configuration

No new settings and no secrets.
